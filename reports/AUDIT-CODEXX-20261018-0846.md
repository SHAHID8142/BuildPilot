`install.sh:340-348`  **BLOCKER**  A failed backup does not stop the subsequent destructive replacement of an existing managed skill.

**Evidence.**


`backup_existing_skill` explicitly returns 1 when `mkdir`, `cp -R`, or reaching the backup root fails (`install.sh:296-297`), but `sync_core_skill` ignores that status. A full disk, permissions failure, or unreachable backup directory therefore does not prevent `rm -rf`.

**Why this matters.** A user who customized `/sps`, `/sps-cms`, or `/sps-seo` can lose those edits during an update even though the installer advertises a restore path. This is not theoretical code execution; it is a destructive write after a failed safety step.

## Layer 4 — Code-Gen Injection

`framework/sps2/tools/gen_law_test.py:123-139`  **MINOR**  `_rel()` accepts NUL and several control/Unicode line separators that are later embedded raw in the generated Python docstring.

**Evidence.**

```text
rel 'A\tB'   -> 'A\tB'
rel 'A\x00B' -> 'A\x00B'
rel 'A\u2028B' -> 'A\u2028B'
rel 'A\u2029B' -> 'A\u2029B'
fixture '\x00' -> ['junk = tmp / \'\\x00\'', ...]
```

`_rel()` blocks quotes, backslashes, CR, LF, backtick, and dollar, but not other control characters or U+2028/U+2029. `target_file` is formatted directly into the docstring at lines 252 and 300. In-memory compile probes showed NUL makes Python source invalid; NEL/LS/PS are accepted inside a string. No arbitrary code-injection payload was found because the quote characters needed to close the docstring are rejected. The result is a possible invalid or confusing generated test, not demonstrated remote code execution.

**Why this matters.** A hostile ledger can make an apparently approved generated test syntactically invalid or semantically misleading, turning a green human gate into a broken CI run.

**Suggested fix.** Reject all C0/C1 controls, Unicode line/paragraph separators, and NUL in `_rel()`; render `target_file` with `repr()` everywhere it appears in generated source.

**Other interpolated fields.** `--approved-by` rejects control characters, non-ASCII, quotes, and overlong values. `check_id` is ASCII-restricted and converted through `snake()`/`class_name()`. Ledger `message` values reach generated code through Python `repr()`. The following in-memory checks rejected hostile values:

```text
approved 'A\nB' REJECT; 'A\rB' REJECT; 'A\tB' REJECT; 'A\x00B' REJECT
approved 'A\u2028B' REJECT; 'A\u2029B' REJECT; 'A"B' REJECT; 'A\\B' REJECT
```

No arbitrary Python/shell injection was empirically achieved. No other tool that writes Python or shell from CLI/JSON input was found.
