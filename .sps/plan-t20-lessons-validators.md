# T-20 Plan: Lessons → Validators Automation

## Goal
When `check_laws.py` rejects the same doc mistake twice, auto-generate the
negative test that locks the rule in — so a lessoned mistake can never
silently regress. Closes the loop: lesson (human/agent) → rule in doc →
machine check → regression test, with the last step automated.

## Trigger definition (exact)
A "repeat rejection" = check_laws.py returns a FAIL line with the same
`(check_id, target_file)` pair on two separate runs, where the earlier run
is recorded in a rejection ledger. The ledger lives at
`.sps/law-rejections.jsonl` (one JSON object per line: timestamp, check_id,
target_file, message). It is appended by a new wrapper subcommand, not by
silent observation — nothing watches the user's terminal.

## Approach
1. **Ledger writer** — `scripts/sps-lawlog.sh` (+ mirror): wraps
   `check_laws.py`, appends each FAIL line to `.sps/law-rejections.jsonl`
   (gitignored in client projects; in this repo it is governance data and
   committed). Subcommands: `run` (check + log), `show` (repeat summary).
2. **Test generator** — `framework/sps2/tools/gen_law_test.py`: given a
   `(check_id, target_file)` seen ≥2 times, emits a negative test file
   `framework/sps2/tests/test_law_regress_<check_id_snake>.py` containing a
   fixture that reproduces the violation and asserts the check fires.
   Generated tests carry a header: `# AUTO-GENERATED by gen_law_test.py
   (T-20) — reviewed by: <user/date>` and are NOT valid until that header's
   reviewer field is filled (validator refuses unreviewed generated tests).
3. **Human gate** — generation proposes; the user approves (LESSONS.md
   hard rule: nothing auto-lands). `gen_law_test.py --apply` writes the
   test only after an explicit `--approved-by <name>` flag.
4. **check_laws.py extension** — new check: `GENERATED_TEST_UNREVIEWED`
   fires when a generated test lacks a filled reviewer field.
5. **SKILL.md + LESSONS.md** — document the loop: lesson → rule →
   `sps-lawlog run` → repeat detected → propose test → approve → test in
   battery. New mode section `### Law Log`.

## Gates
- Section DoD applies (≤500 lines/script, mirrors in sync, no stubs)
- Manifest pinning for new scripts/ files (orchestrator, after build)
- Negative tests: generated test must FAIL before the fix exists and PASS
  after (proven on a scratch copy, never on the live tree)
- Full battery + validators + CI before merge

## Out of scope
- Auto-approval of generated tests (permanent — user gate stays)
- Auto-editing skill docs from rejection data (that stays a human/agent
  lesson-review act; this task only automates the regression-test half)
